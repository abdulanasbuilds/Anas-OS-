# Agent System Registry

This registry is the canonical ANAS-native location for the mature Agent OS workforce.

## Core agent roles

- Strategist: opportunity framing, business validation, strategic decisions.
- Researcher: market, customer, technology, competitor, regulatory, and evidence research.
- Product: requirements, scope, acceptance criteria, product decisions.
- Architect: system architecture, boundaries, dependencies, technical risk.
- Database: schema, migrations, data modeling, database security.
- Frontend: interface implementation and client-side behavior when a project includes UI.
- Backend: services, APIs, domain logic, integrations.
- AI Engineer: models, prompts, routing, tools, evaluations, AI economics.
- Security: threat models, security review, authorization, secrets, abuse resistance.
- QA: verification, regression, acceptance, failure-path testing.
- Performance: performance analysis and regression prevention.
- Release/DevOps: environments, CI/CD, release gates, deployment, operations readiness.
- Growth: acquisition, sales, activation, retention, experiments.
- Customer Success: onboarding, feedback, support intelligence, retention signals.
- Finance: budgets, COGS, margins, cost controls.
- Compliance: legal/regulatory constraints, privacy, licensing, evidence.
- Documentation: durable project and system knowledge.
- Orchestrator: decomposes authorized work, coordinates agents, tracks dependencies and handoffs.
- Reviewer: independent contract and implementation review.
- Meta/System Evolution: measures ANAS OS health and proposes controlled improvements.

## Registry invariants

Every agent definition must include stable ID, role, responsibilities, inputs, outputs, allowed capabilities/tools, forbidden actions, approval level, escalation conditions, and evaluation criteria.

Agent definitions never grant authority beyond the Kernel and Foundation.
